## 已确认

### 2026-08-26｜五路任务、独立工作树与跨设备检查点

- 长期工作拆为主／集成、内容、作品／视觉、流体、动效／交互五个对话；PR 就绪时再使用短期独立审核对话。
- 每个开发对话使用独立分支和工作树，不在同一目录来回切分支，也不同时修改共享入口。
- 聊天压缩、暂停或切换 Windows／macOS 前，提交并推送检查点，在 Draft PR 记录已完成、未完成、验证、风险和下一步。
- 当前 Windows 负责代码验证，macOS 负责现有视觉检查；跨平台 CI 稳定后再设为 `main` 的必需检查。

### 2026-08-24｜采用纵向切片开发

- 不采用“先做完整底基、最后才验证高级交互”的顺序。
- 先用占位内容跑通 `HELLO. → 首页 → 一个作品 → 菜单 → 播放器 → 基础动效 → 手机降级`。
- 纵向切片通过后，再铺开全部作品、真实媒体和视觉精修。

### 2026-08-24｜最终目标

- 制作一个具有鲜明个人色彩、同时展示视频与图片、整体具有高级感的个人介绍与作品页面。
- 高级感是方向性目标，后续通过真实素材、层级、留白、字体和动效共同验证。

### 2026-08-24｜橙色保持开放

- 橙色不是强制色，也不是禁止色。
- 是否使用必须等真实作品和完整页面放在一起后判断。
- 如果后续舍弃，移动到“已舍弃”并补充理由。

### 2026-08-24｜当前 PR 只整理文档

- 允许更新目标、设计方向、修改意见、Agent 分工和仓库规则。
- 不在本 PR 修改任何前端代码或视觉实现。

### 2026-08-23｜定位与首屏

- 定位为“杨玉峰｜影像导演 × AI 视觉创作者”。
- 使用短 `HELLO.` 文字开场，随后直接进入作品。
- 姓名、定位和导航必须在开场后立即清楚可见。

### 2026-08-23｜作品与导航

- 首页作品优先，使用重点作品与轻量索引的组合。
- 导航层集中展示能力、About、邮箱与微信入口。
- 点击作品使用全屏观看空间，不建立传统案例详情长页。

### 2026-08-24｜动效修改意见

- 光标流体需要形成全局连续反馈，不能只在局部出现。
- 菜单和播放器需要渐显或两侧滑入的场景转场。
