# Agent 分工与任务边界

## 1. 四个责任角色

| 角色 | 最终负责人 | 核心责任 |
| --- | --- | --- |
| 产品负责人 | 杨玉峰 | 最终目标、内容范围、优先级和取舍 |
| 视觉负责人 | 杨玉峰 | 视觉方向、真实素材适配和页面截图验收 |
| 技术／集成负责人 | 主 Agent | 技术边界、共享文件、依赖、冲突与 PR 集成 |
| QA／审核负责人 | 独立审核 Agent 或人工复核 | 测试、桌面／手机、性能、可访问性和证据 |

Agent 可以辅助提出方案，但产品和视觉方向只有杨玉峰能够最终确认。

## 2. 工作包拆分

| 工作包 | 直接负责人 | 负责 | 明确不负责 | 前置依赖 |
| --- | --- | --- | --- | --- |
| 目标与设计文档 | 文档 Agent | 目标、方向、决定记录、文档一致性 | 前端代码与视觉实现 | 用户提供方向 |
| 内容与素材 | 内容 Agent | 作品清单、标题、分类、角色、媒体交接 | 虚构数据与重新设计页面 | 内容结构确认 |
| 视觉系统 | 视觉 Agent | 色彩、字体、版式、媒体构图建议 | 自行批准最终方向 | 真实素材到位 |
| 全局流体 | 流体 Agent | 流体模块及其降级与性能 | 菜单、播放器、作品数据 | 视觉方向与测试基线 |
| 场景转场 | 动效 Agent | 菜单、播放器的打开与关闭动效 | Shader、作品内容、最终色板 | 动效原则确认 |
| 集成 | 技术／集成 Agent | 共享入口、全局样式接口、冲突处理 | 替用户决定产品或审美 | 各模块达到交付条件 |
| 独立验收 | QA／审核 Agent | 测试、截图、交互、性能与缺陷报告 | 重做功能或扩大范围 | 集成版本可运行 |

## 3. 推荐先后关系

`文档确认 → 素材准备与视觉系统 → 流体／场景转场并行 → 技术集成 → 独立验收 → 杨玉峰最终审核 → 合并`

前一步没有形成可检查的交付物，后一步不以猜测代替依赖。

## 4. 避免重复劳动

- 每个 Issue 只有一个直接负责人
- 开工声明必须写：目标、负责范围、明确不做、前置依赖、验收条件
- 两个 Agent 不得同时修改同一共享文件
- `App.tsx`、全局样式和跨模块接口默认只由技术／集成负责人修改
- 发现任务重叠时先暂停重叠部分，由技术负责人重新划边界
- 纯技术冲突由技术负责人解决；影响产品或视觉方向时交给杨玉峰裁决

## 5. 当前文档任务边界

- 负责：`PROJECT.md`、`CONTRIBUTING.md`、`docs/*.md` 的目标与约束整理
- 不负责：任何 `src/`、样式、组件、动效和媒体实现
- 交付：只进入当前 Draft PR，由杨玉峰亲自审核后决定是否合并
