# Agent 分工与任务边界

## 1. 四个责任角色

| 角色 | 最终负责人 | 核心责任 |
| --- | --- | --- |
| 产品负责人 | 杨玉峰 | 最终目标、内容范围、优先级和取舍 |
| 视觉负责人 | 杨玉峰 | 视觉方向、真实素材适配和页面截图验收 |
| 技术／集成负责人 | 主 Agent | 技术边界、共享文件、依赖、冲突与 PR 集成 |
| QA／审核负责人 | 独立审核 Agent 或人工复核 | 测试、桌面／手机、性能、可访问性和证据 |

Agent 可以辅助提出方案，但产品和视觉方向只有杨玉峰能够最终确认。

## 2. 推荐的五个长期对话

五个对话不是五个人同时改同一份代码，而是五条互不重叠的工作线：

| 对话／Agent | 负责 | 默认文件边界 | 明确不负责 |
| --- | --- | --- | --- |
| 主／集成 Agent | 目标文档、任务排序、共享入口、依赖、冲突和 PR 集成 | `PROJECT.md`、`AGENTS.md`、`docs/`、`src/App.tsx`、`src/main.tsx`、全局样式与构建配置 | 替用户决定最终审美 |
| 内容 Agent | 真实作品、标题、分类、角色、个人资料和媒体交接 | `src/content/`、`docs/content-inventory.md` | 页面结构、动效和虚构数据 |
| 作品／视觉 Agent | 作品区、排版、色彩和真实媒体构图；Windows／macOS 均可检查，当前自动截图脚本仅兼容 macOS | `src/features/works/`，全局样式只提交提案给集成 Agent | 流体、播放器逻辑和自行批准方向 |
| 流体 Agent | 全局流体、降级、性能和对应测试 | `src/features/fluid/` | 菜单、播放器、作品内容 |
| 动效／交互 Agent | 开场、导航、播放器、焦点与滚动交互 | `src/features/intro/`、`src/features/navigation/`、`src/features/player/`、相关 hooks | Shader、作品数据和最终色板 |

PR 就绪时再开一个短期独立审核对话读取改动和验证证据；审核对话默认不持有开发分支，也不直接重做功能。这样长期上下文保持在五条主线内，审核仍然独立。

## 3. 推荐先后关系

`基线稳定与协作保护 → 文档确认 → 素材准备与视觉系统 → 内容扩展 → 流体／场景转场精修 → 独立验收 → 杨玉峰最终审核 → 合并`

仓库现有原型已经提供一条可运行的纵向切片，接下来先让测试与跨平台协作稳定，再用真实素材验证并扩展。前一步没有形成可检查的交付物，后一步不以猜测代替依赖。

各阶段的开始条件、通过证据和五个对话创建方式见 [项目进度书](superpowers/plans/2026-08-26-project-progress-gates.md)。

## 4. 纵向切片验收门槛

- 可以从 `HELLO.` 进入首页并看到一个作品
- 菜单和播放器可以打开、关闭，Esc 与焦点恢复不失效
- 基础转场和光标流体至少有可运行的桌面版本
- 手机、减少动态和 WebGL 不可用时仍有完整静态体验
- 没有明显溢出、控制台错误或不可恢复的滚动状态

门槛未通过时只修切片，不继续批量填充内容。

## 5. 避免重复劳动

- 每个 Issue 只有一个直接负责人
- 开工声明必须写：目标、负责范围、明确不做、前置依赖、验收条件
- 两个 Agent 不得同时修改同一共享文件
- `App.tsx`、全局样式和跨模块接口默认只由技术／集成负责人修改
- 发现任务重叠时先暂停重叠部分，由技术负责人重新划边界
- 纯技术冲突由技术负责人解决；影响产品或视觉方向时交给杨玉峰裁决
- 同机上下文压缩或暂停前覆盖更新工作树内的 `.agent-state/STATUS.md`；只有换设备、备份或删除工作树前才提交并推送

## 6. 当前文档任务边界

- 负责：`PROJECT.md`、`CONTRIBUTING.md`、`docs/*.md` 的目标与约束整理
- 不负责：任何 `src/`、样式、组件、动效和媒体实现
- 交付：只进入当前 Draft PR，由杨玉峰亲自审核后决定是否合并
