# 作品精选与工作经历项目归属设计

- 日期：2026-09-01
- 状态：待用户书面复核
- 范围：先将碧云泉净水器项目从独立精选区移至酷我贸易经历下方

## 1. 目标

首页同时服务潜在客户、合作方与招聘方，因此不能只做作品墙，也不能把所有商业成果埋进长篇履历。本轮采用“独立能力精选在前，雇主项目归属在后”的混合结构：

1. `02 精选作品` 展示不依附某段雇佣关系的能力证明，例如 AI 视频、调色与独立影像。
2. `03 工作经历与商业项目` 保持倒序经历，并允许每段经历挂载零个或一个当前代表项目。
3. 碧云泉净水器项目归属于酷我贸易（徐州）有限公司，必须紧跟该经历展示，不再作为通用精选作品重复出现。

## 2. 页面顺序

```text
Hero
├── 01 关于我
├── 02 精选作品
│   ├── 独立影像精选组
│   └── 调色／商业影像精选组
└── 03 工作经历与商业项目
    ├── 兴海集团
    │   └── 未来可选代表项目
    ├── 广州哲品家居用品有限公司
    │   └── 未来接入公道杯／游侠纯钛茶具项目
    └── 酷我贸易（徐州）有限公司
        └── 碧云泉净水器项目（本轮接入）
```

联系／结束区仍是后续独立任务，不混入本轮。

## 3. 组件边界

### 3.1 精选作品容器

当前 `ProjectShowcase` 同时承担独立影像卡组、净水器标题、净水器媒体和项目说明，职责过多。本轮将它收敛为“精选作品容器”，只负责：

- `#works` 锚点；
- 精选作品章节导览；
- 两组现有媒体卡组；
- 未来新增精选内容的稳定入口。

它不再渲染净水器项目，也不持有净水器专属标题与项目档案。

### 3.2 可复用商业项目组件

将现有净水器标题、元信息、媒体、播放器按钮、项目档案和制作过程抽成独立商业项目组件。组件继续复用现有：

- `LazyPreview`；
- `Project` 数据；
- `onOpenProject` 播放器入口；
- 静音短预览／减少动态降级；
- 当前视觉样式和净水器文案。

组件不得复制媒体节点，也不得改变视频加载策略。

### 3.3 经历项目插槽

`ExperienceSection` 根据稳定经历标识渲染可选项目插槽。经历数据增加稳定 `id`，例如：

- `xinghai`
- `zhepin`
- `kuwo`

页面集成层负责把 `kuwo` 映射到净水器商业项目组件。经历内容层只声明雇主身份，不直接导入播放器或作品组件。这样项目身份与雇主身份不会混在同一个 ID 中，未来兴海、哲品接入不同媒体形态时，也不需要复制整段经历布局。

## 4. 数据与交互流

1. `App` 继续唯一持有当前播放器项目和打开按钮引用。
2. 精选作品卡组与酷我贸易下方的净水器项目都通过同一个 `onOpenProject` 打开现有全屏播放器。
3. 关闭播放器后，焦点返回实际触发播放的按钮；净水器移动位置后仍需通过真实浏览器验证。
4. `#works` 继续落到独立精选区。净水器不获得重复的 `works` ID。
5. 净水器只渲染一次，避免两处预览同时加载和数据归属混乱。

## 5. 视频生命周期硬边界

本轮不得修改或弱化已经由用户验收的精选卡组修复：

- 累计 `warmedIndices` 保留本次卡组会话中已预热的视频节点与解码状态；
- `transitioningIndex` 在动画开始时即让入场视频播放；
- 常态一条播放，约 0.68 秒切换期最多两条同时播放；
- 活动索引提交不二次调用 `play()`；
- 已解码的暂停帧可进入合成层；
- `prefers-reduced-motion` 下不挂载预览视频；
- 强制回归路径为 `01→02→03→04→03→02→01`。

净水器项目的移动只改变页面归属和 DOM 位置，不改变上述独立精选卡组行为。

## 6. 响应式与视觉规则

- 桌面端：净水器项目紧跟酷我贸易经历主体与数据说明，视觉上属于同一经历，但保留项目自身的标题层级与媒体展示空间。
- 中等宽度：经历正文与项目媒体依次纵向排列，不通过绝对定位强行并排。
- 手机端：经历先于项目，项目媒体保持可点击区域、播放按钮和原始视觉比例，无横向溢出。
- 不把兴海或哲品渲染成空视频框；没有真实项目素材时只展示经历内容。

## 7. 实施范围

允许修改：

- `src/App.tsx` 及其直接测试；
- `src/features/works/ProjectShowcase.*`；
- 新增或抽取的商业项目组件及直接测试；
- `src/features/experience/ExperienceSection.*`；
- `src/content/experience.ts` 及直接测试。

明确不做：

- 不修改净水器文案、数据、媒体路径与播放器设计；
- 不新增兴海或哲品的项目内容；
- 不调整 Hero、About、导航、全局字体和全局样式；
- 不修改 `LongFormProjects`、`LazyPreview` 的卡组生命周期实现；
- 不提交 `output/`、本机截图或本机绝对路径。

## 8. 验收标准

### 内容与结构

- 页面只出现一次“净水器项目”及其视频预览。
- 净水器位于酷我贸易经历的正文、成果和数据之后，且仍处于 `03 工作经历与商业项目` 章节。
- 经历顺序保持兴海集团 → 哲品 → 酷我贸易。
- 独立精选区仍位于工作经历之前，并保留两组现有卡片。
- `#works` 继续指向独立精选区。

### 交互与可访问性

- 净水器短预览按现有规则加载、暂停和降级。
- 点击净水器可打开正片；关闭后焦点返回新的触发按钮。
- 精选卡组桌面滚轮、手机操作、边界放行和播放器滚动锁不回归。
- 页面不存在重复 ID、重复可访问名称导致的误触发或重复媒体请求。

### 验证

- 新增结构归属测试：净水器节点在酷我贸易经历内部且只出现一次。
- 保留卡组正反路径和视频节点身份测试。
- 运行 `npm run test:run`、`npm run typecheck`、`npm run lint`、`npm run build`、`git diff --check`。
- 真实浏览器检查 1440、960、390 三种宽度：无横向溢出、控制台错误、页面错误或失败媒体请求。
- 人工确认净水器与酷我贸易的视觉归属清晰，独立精选区没有残留净水器专属标题。

## 9. 已知风险与控制

- **重复渲染**：抽取后旧组件若未完全移除净水器，会导致两套媒体请求。通过 DOM 数量与请求记录验证。
- **播放器焦点**：项目移动到经历内部后，关闭播放器必须使用新的触发按钮引用。通过键盘测试和真实浏览器验证。
- **CSS 上下文耦合**：现有净水器样式可能依赖 `ProjectShowcase` 父级。优先迁移局部样式，不把规则扩散到全局。
- **章节语义**：精选作品仍是 `02`，工作经历仍是 `03`；商业项目属于经历内容，不新增虚假的第四章节。
- **卡组回归**：不得为适配新结构重写 `LongFormProjects` 或 `LazyPreview`，相关文件保持现有检查点实现。
