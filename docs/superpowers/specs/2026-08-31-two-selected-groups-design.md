# 两组精选作品与经历案例重排设计

## 目标

将当前“一个四卡组 + 下方重复剧情视频”的作品区改为两个互相独立的四卡精选组；在精选之后新增能力证据区，再让碧云泉与哲品的商业视频和数据分别跟随对应工作经历展示。页面不使用项目切换器，也不把八支视频合成一个卡组。

## 页面顺序

1. Hero
2. `01 ABOUT / 关于我`
3. `02 SELECTED WORKS / 精选作品`
   - `02.01 精选影像 · 第一辑`：现有旅拍、剧情、MacBook、棋局四支
   - `02.02 精选影像 · 第二辑`：用户明确指定的另外四支
4. `03 CAPABILITY PROOF / 能力边界`
5. `04 EXPERIENCE / 工作经历`
   - 兴海集团：任职与团队成果，不强制配置作品视频
   - 广州哲品家居用品有限公司：经历、茶具视频、公道杯 `80万元／1:7`
   - 酷我贸易（徐州）有限公司：经历、碧云泉视频、`45万元／1:5`、UV 与 BPM
6. `05 CONTACT / 联系`

## 精选作品设计

两个四卡组复用同一 `ProjectMediaDeck` 组件，但各自持有独立活动索引、播放状态和滚轮边界。

- 第一辑继续使用现有四支媒体和正式文案。
- 第二辑只接受用户明确指定的四个媒体文件；系统不得扫描目录、按文件名猜测或复用第一辑。
- 第二辑四支未全部确认时，整个第二辑保持草稿，不渲染空卡或“待补充作品”。
- 鼠标位于某一卡组时，滚轮只切换该组素材；到达首尾后放行页面滚动。
- 手机使用滑动和明确按钮，不用滚轮语义。
- 页面只加载当前卡组当前素材的短预览，其他素材显示海报。
- 删除当前固定剧情视频区域，剧情短片仅在第一辑中出现一次。

## 能力证据设计

能力区位于精选和工作经历之间，先说明能力边界，再给出职业来源。主体四项：

1. AI 影像制作
2. 商业影像调色
3. 全链路影像制作
4. 商业内容与投放闭环

每项只引用真实媒体或商业案例 ID，不复制商业指标全文。没有真实证据的能力不渲染视频占位。

## 工作经历与商业案例

Experience 保持逆时间顺序。商业案例成为经历条目的子内容，而不是精选区的第三、第四个项目。

- 兴海保留 `约6人`、`约1周→3天` 等任职期成果。
- 哲品条目承载公道杯和游侠纯钛茶具内容；`80万元／1:7` 只归公道杯单条素材。
- 酷我条目承载碧云泉项目；`45万元／1:5` 必须表述为同一条素材单月最高投放消耗与投产比；UV 约 6 元与 BPM 约 6000 保持原统计名。
- About、能力区和经历摘要不得重复上述指标，只能链接到对应案例。

## 数据边界

- `selectedWorkGroups`：只保存两组精选及其媒体。
- `capabilityProofs`：只保存能力声明与证据引用。
- `experienceContent`：保存三段经历；哲品和酷我条目内保存各自商业案例。
- 未确认字段使用 `null` 或空数组并由 `publishStatus` 阻止公开；禁止访客看到内部占位词。

## Agent 所有权

- 主／集成：规范、App、章节顺序、锚点和最终合并。
- 内容：`src/content/` 事实源和对应测试，不改组件。
- 动效：`ProjectMediaDeck`、滚轮／触摸／键盘、懒加载、播放器和闪帧测试。
- 媒体：只处理用户明确指定的文件，派生海报、H.264 预览和兼容正片。
- 作品视觉：组件接口冻结后负责局部 CSS、桌面／手机排版；不改交互状态机。
- QA：只读检查，不直接重做功能。

## 非目标

- 不建立项目名称切换器。
- 不建立单一八卡组。
- 不从本地目录自动挑选第二辑。
- 不把碧云泉或哲品混入第二辑。
- 不为了填满页面虚构联系方式、职责、媒体或指标。

## 验收标准

- 两个独立四卡组，第一辑与第二辑媒体零重复。
- 第二辑媒体全部来自用户明确指定。
- 固定剧情重复区域消失。
- 两个卡组状态、滚轮与媒体请求互不影响。
- 正反切换至少 12 次，无旧卡闪回或未解码视频提前覆盖海报。
- 能力区位于工作经历之前。
- 商业视频和指标只出现在对应经历案例。
- 1440、960、390 无横向溢出，键盘焦点、触摸、播放器开关与滚动锁正常。
- 全量测试、类型检查、Lint、Build 与 `git diff --check` 通过。
