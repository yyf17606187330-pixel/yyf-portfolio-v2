# 视觉与体验方向

**状态：本地首版已形成 `Hero → 01 关于我 → 02 作品集`；关于我按编辑式参考完成 3:4 占位，作品区已接入三项真实比例媒体。用户已确认全局苹方与首屏文字／人物间距收紧；结尾叠化仍停用，既有 Hero、按钮时序、播放器与作品交互保留。**

## 1. 设计目标

页面要有明确的个人气质，不像通用作品集模板，也不做传统简历式长页面。视频与图片共同构成作品空间，整体感受应克制、成熟、有影像质感。

“高级感”主要来自：真实素材质量、画面尺度、留白、字体层级、动效节奏和细节一致性；不依赖大量渐变、玻璃卡片或装饰粒子。

## 2. 第一段体验

- 开屏直接展示满幅肖像视频的首帧、姓名、定位、强调句与完整简介；不再把简介藏到第二幕。合格桌面开场按钮隐藏
- 首屏以用户新参考图的文字／人物关系为依据：桌面文字组向人物侧收拢，姓名字级与字距适配苹方；正文右缘保持在脸部安全区之外，延后出现的 CTA 与文字左缘对齐。手机仍使用原有页面边距，不照搬桌面内缩
- 顶部采用两枚紧凑胶囊，右侧为 `Y.`／微信身份标识；不复制参考网站的奖项标识
- 桌面滚动时视频逐帧推进，媒体围绕人物焦点从 1.00 放大至 1.10，不叠加横向平移
- 顶部胶囊与右侧标识在滚动进度 16%–56% 缓慢浮现；CTA 延后到 82%–100%，成果文案基本呈现后才出现。采用柔和的 sine.inOut，之后保持显示，回到顶端重新隐藏；加载视频前已隐藏，避免首帧闪现
- 首屏文案仍渐隐，后段经验成果仍渐显上移；按钮与文字方向不同，但共用视频滚动进度。桌面作品按钮单独位于左下预留区，不压住成果文案
- 末屏采用左侧中部 2×2 数据，文字区域限制在画面左侧负空间；结尾选睁眼帧，避免停在未完成的眨眼上
- 视频叠化到新照片的效果已被用户否定并撤回；当前本地样板使用用户后续提供的视频和首帧海报，不自动重新接入该静帧
- 移动端、粗指针、减少动态、媒体失败或内容高度放不下时，不强行 pin，按钮立即恢复；完整介绍与成果按正常文档流显示。合格桌面等待 metadata 时不 pin，但控件保持开场隐藏
- 独立 `HELLO.` 开场暂不接入本轮 Hero 原型，不增加加载 Logo 或百分比进度条

参考 Gavin 与 Tomoya 的短文字节奏，只借鉴进入方式，不复制页面、Logo 或素材。

## 3. 页面结构

- 页面顺序固定为 `Hero → 01 关于我 → 02 作品集`；Hero 继续用完整介绍与简洁成果建立身份
- Hero 与关于我之间使用一条全宽双细线编辑式导览：左侧时间，右侧依次为个人定位、内容策略、影像制作和 AI／协作；桌面横向展开，手机折为 2×2，不做跑马灯或额外卡片
- 关于我借鉴编辑式长页：顶部章标、深炭主句与暖色斜体强调、双细线能力条、左文右图、首字强调、两段正文与署名；下方以细线组织 6 组能力范围和 3 组实践成果，不做卡片墙或履历时间线
- 关于我桌面保持左文右侧 3:4 肖像／工作照占位，下方双列；手机依次为标题、8 项能力、引言、肖像、正文、能力范围、实践成果和作品入口
- `#about` 与 `#works` 保留独立锚点；作品章标为 02，长片使用作品子级编号
- 重点作品使用较大画幅，其余作品进入轻量索引
- 作品总量目标为 10–15 个，横屏、竖屏、视频和图片都要适配
- 分类为影像、AI 视频、摄影、设计与交互
- 全屏导航集中说明“我是谁、我会什么、关于我、如何联系”
- 点击作品进入全屏观看空间，不增加冗长案例详情页

作品组织借鉴 Electra 的大小网格、分类索引与全屏播放思路，但不复制其源码、品牌或媒体。

## 4. 媒体表现

- 封面负责第一眼构图，短预览负责建立动态感，全片由用户主动打开
- 视频与图片应处于同一视觉体系，不把图片当作低一级占位内容
- 重点项目优先选择商业影像、AI 视频、摄影各一个，体现能力跨度
- 真实媒体未到位前只使用明确占位，不虚构客户、成绩或账号数据
- 当前作品首版包含净水器 9:16、旅拍 2:1 与剧情短片 16:9；三者保持原生比例或 `object-fit: contain`，不裁切、不拉伸、不加滤镜
- 视频画面不叠加滤镜、对比度或颗粒；静音预览可暂停，离屏、页面隐藏或打开正片时停止，减少动态时保留封面
- 原 HEVC Main10 完整文件保持不变，点击后才请求；失败时可使用同色彩意图的 H.264 兼容副本。保留 Rec.709，不承诺跨设备显示完全相同

## 5. 动效语言

- 光标流体反馈应贯穿桌面作品空间，而不是只出现在局部区域
- 流体更适合轻微影响文字、图标或按钮反馈，不增加塑料感粒子球
- 菜单与播放器采用渐显、遮罩或两侧滑入，形成统一的场景转场
- 不是所有区块都需要飞入；动效应帮助观看层级，而不是持续抢注意力
- 触屏、减少动态和 WebGL 不可用时必须保留清晰、完整的静态体验

## 6. 色彩与字体

- 当前关于我与作品区采用局部暖米杏背景、深炭正文、陶土橘强调；全站标题、正文、导航、按钮与播放器统一使用设备本机的 `苹方-简 → PingFang SC → Noto Sans SC → Microsoft YaHei`，移除 Syne／Manrope 字体加载，不分发字体文件
- 橙色目前是允许选项，不是默认色，也不是禁用色
- 如果后续判断橙色不适合，再把决定和原因写入 `decision-log.md` 的“已舍弃”部分
- 科技蓝绿色不作为默认方向，但可以在真实素材证明合适时重新评估
- 色彩选择必须服务作品与个人气质，不能为了显得高级而牺牲媒体本身
